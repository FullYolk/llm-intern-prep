## httpx基础(http请求)
* httpx.get()：取数据 获取/查询 只能将数据拼在url后面(还有args参数) 所有人都能看见，且URL长度有限制（2KB）
* httpx.post()： 发数据 提交/创建 将数据放在HTTP请求的Body(请求体里面) URL上不能看到 数据大小没有要求
* params参数：将数据追加到args下（url后），只能传简单的键值对 主要配合GET
* json= 会把数据放入请求体，适合传复杂结构；如果使用 HTTPS，传输过程会被加密。Body 大小也有服务端限制，并非无限。
* .json()：会把 JSON 响应解析成 Python 对象，可能是 dict，也可能是 list、str、int 等。
## logging基础 参数调用：level format filename(若存进文件)
* 真实项目里使用logging:需要日志保存 便于定位错误 检测运行状况
* INFO：用于代码正常运行时提供必要信息
* WARNING：用于警告
* ERROR：用于捕获异常时/报错时
## 装饰器基础
* 本质上是给函数套一层功能
* @app.get()属于注册型装饰器 完全不改变原函数 目的实际上是记录
* 平时常用的是属于包装增强型 给原函数增加功能使用
* 这些需求重复性强 增加的功能较为简单 且出现的频率高 适合使用装饰器
* 写装饰器时 @wraps(func)是好习惯
## 异步编程
* 同步阻塞会阻塞当前线程的执行流程；异步等待可以在等待 IO 时把控制权交还给事件循环，让其他协程继续执行。
* 异步等待时能够让出CPU 在IO等待过程中同步进行其他工作 提高效率
* async def允许了异步运行 await是异步等待
* 这里的协程并非多线程 而是在同一个线程中 由同一个线程或核心进行异步操作
* 流式输出 HTTP请求等需要大量网络或IO等待 属于IO密集型 Python 中，IO 密集型可以用 async 或多线程；CPU 密集型通常考虑多进程或原生计算库。 在进行流式输出或网络等待时 单线程+异步内存开销极低 省去了上下文切换的开销 让出机制恰好适合IO密集型
